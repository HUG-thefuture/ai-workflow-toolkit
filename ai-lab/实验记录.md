## 5. 部署中的问题与处理

1. **Dify 登录报 `Invalid encrypted data`**：1.17 前端要求密码字段 Base64 编码；Python/脚本调用控制台时需先编码。
2. **Dify 控制台请求报 CSRF 校验失败**：需携带 `X-CSRF-Token`（取自 `csrf_token` Cookie）。
3. **工作流导入后运行报 `sys.query not found`**：LLM 节点继承了对话记忆模板，清空 `memory.query_prompt_template` 后重新发布。
4. **Qwen3 输出 `<think>` 思考过程**：在 LLM 节点 `completion_params` 中增加 `think: false`。
5. **Dify 法律助手误引第 263 条**：提高检索 `top_k=6`、阈值 0.25、温度 0.1，并在提示词中约束“只引用检索结果中的条文”。
6. **Dify `local_sandbox` 循环重启**：镜像内 `shellctl` 不支持 `--require-auth-token`，移除该参数后健康。
7. **Docker 镜像站限流**：移除 `docker.xuanyuan.me`，改用 `docker.1ms.run` 与 `docker.m.daocloud.io`。
8. **Coze 的 `minio/minio:RELEASE.2025-06-13T11-33-47Z-cpuv1` 已无法拉取**：compose 中改用可用的 `pgsty/minio:latest`（MinIO 重打包镜像，含 `minio`/`mc`，与原有启动脚本兼容）。
9. **Coze Elasticsearch 首次启动被判 unhealthy**：ES 插件初始化耗时超过健康检查窗口，待其启动完成后重新 `up -d` 即恢复。
10. **控制台 API 改图后运行报 `[MISSING_NODE]`**：同步草稿时只替换了边、没有把新增的搜索/模板节点写回 `graph.nodes`，导致悬空边；节点与边必须同时写入后重新发布。
11. **Coze 本地 `/v1/workflow/run` 解析为空**：本地返回的正文嵌套在 `data.data`（`content_type=1`），不是 `data.output`；已修改 `scripts/coze_workflow_test.py` 兼容两种结构。
12. **Dify 重启后工作流报 `Model qwen3:8b not exist`**：Docker Desktop 自启时 `plugin_daemon` 早于 PostgreSQL 就绪，反复崩溃重启；期间 Dify 调用插件拿不到模型实例。等 `plugin_daemon` 日志出现 `local runtime ready`（ollama 插件）后重试即恢复，无需改模型配置。若长时间未就绪，可在数据库健康后手动重启 `docker-plugin_daemon-1`。

## 6. 已知限制

- 旅行助手已接入 DuckDuckGo 联网搜索，但搜索结果受网络与引擎返回质量影响；模型仍可能补充生成具体酒店名称、价格等信息，重要信息需以景区/酒店官方渠道核实。
- Coze 云端 API 已验证可达，但本地 PAT 调用返回 `4100 authentication is invalid`；尚未完成真实云端工作流调用，需云端 PAT 与云端工作流 ID。
- Coze Studio 开源版与云端 API 存在差异，本实验使用本地 PAT + `/v1/workflow/*` OpenAPI 完成调用。
- Coze 的 MinIO 使用社区重打包镜像替代原固定版本，仅用于本地实验。
- 本地 Ollama 模型为 8B 规模，生成质量与响应速度受硬件（WSL 约 8GB 内存）限制。
